# Feature Specification: 学习音效反馈（Sound Effects）

**Feature Branch**: `004-sound-effects`

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "功能基本齐全了 但是太单调 我想加一些音效"（台词与事件映射由用户于 2026-09-30 指定）

## Clarifications

### Session 2026-09-30

- Q: 连对（连杀）的计数应该在什么范围内累计？ → A: 每次点击"开始"（今日测验 / 专项练习）时归零，答错时也归零；不跨测验、不跨会话、不跨天保留
- Q: 进入这五个页面时，开场语音是每次进入都播，还是同一次登录里只播第一次？ → A: 每次进入都播（含从其他页返回与刷新），仅对极短时间内的重复进入做去重
- Q: 进入专项练习页（错题专项 / 错题库专项）时要不要播进入语音？ → A: 不播；仅在该页点击"开始"时播 `Come get some!`
- Q: 学生正在听单词发音朗读时正好触发连杀语音，应该让谁出声？ → A: 单词发音优先，朗读进行中则跳过本次音效语音（不打断朗读、不排队补播）

## User Scenarios & Testing *(mandatory)*

<!--
  IMPORTANT: User stories should be PRIORITIZED as user journeys ordered by importance.
  Each user story/journey must be INDEPENDENTLY TESTABLE.
-->

### User Story 1 - 连续答对播报与答错复位（Priority: P1）

学生在今日测验 / 错题本专项 / 错题库专项中作答时，系统按"连续答对"的题数播放递进的英文语音：连对第 1 题 `First blood`、第 2 题 `Double kill`、第 3 题 `Triple kill`……直到第 10 题 `Deca kill`；一旦答错，播放 `Storm the front.` 并把连对计数清零，下次答对从 `First blood` 重新开始；连对超过 10 题后，第 11 题及以后每题播放 `Good job`。语音语气高昂激情，做题像打连杀一样有节奏。

**Why this priority**: 这是"单调感"最主要的来源，也是用户指定的核心玩法；独立可用、独立可测，做完就是一个有价值的 MVP。

**Independent Test**: 打开任意测验页开始作答 → 连答对 3 题应依次听到 `First blood` / `Double kill` / `Triple kill`；答错一题听到 `Storm the front.`；再答对回到 `First blood`；连答对 12 题则第 11、12 题均听到 `Good job`。

**Acceptance Scenarios**:

1. **Given** 音效已开启且已有用户交互，**When** 学生在测验中连续答对第 N 题（1 ≤ N ≤ 10），**Then** 播放该 N 对应的连杀台词（1=First blood、2=Double kill、3=Triple kill、4=Quadra kill、5=Penta kill、6=Hexa kill、7=Hepta kill、8=Octa kill、9=Nona kill、10=Deca kill）
2. **Given** 学生已连续答对 10 题，**When** 继续答对第 11 题及以后任意一题，**Then** 每题播放 `Good job`
3. **Given** 学生正在连对中，**When** 答错一题，**Then** 播放 `Storm the front.`，连对计数清零，且此时仍保留原有的文字 / 颜色对错提示
4. **Given** 学生答错后连对已清零，**When** 再次答对一题，**Then** 播放 `First blood`（从头开始计数）
5. **Given** 学生连续快速答题，**When** 上一条语音尚未播完就触发下一条，**Then** 新的语音立即覆盖上一条，不排队堆积、不叠加成噪声
6. **Given** 音效已关闭，**When** 学生完成上述全部操作，**Then** 全程无任何声音，答题流程与对错反馈完全不受影响

---

### User Story 2 - 页面进入与"开始"语音（Priority: P2）

学生进入主要页面时听到一句高昂的开场语音，点"开始测验 / 开始专项练习"时听到一句激励语音：首页 `Stick together, team.`、学习页 `OK, let's go!`、测验页 `Fire in the hole!`、错题页 `Bombs on the ground here.`、总结页 `Keep going and stay strong, team.`、开始测验与专项练习 `Come get some!`。除这些之外，**其他任何操作都不发声**（翻页、测验完成、轮次达成、导航切换、按钮点击、登录、设置保存等一律静音）。

**Why this priority**: 这类语音提供场景切换的仪式感与开场激励，依附于既有导航流程；在 P1 之上叠加，不影响 P1 独立可用。

**Independent Test**: 依次进入首页 / 学习 / 测验 / 错题 / 总结五个页面 → 各听到对应的一句语音且互不串台；点击开始测验 → 听到 `Come get some!`；做翻页、点导航、点其他按钮 → 全程无声。

**Acceptance Scenarios**:

1. **Given** 音效已开启，**When** 学生进入首页 / 学习页 / 测验页 / 错题页 / 总结页，**Then** 各播放一次对应台词（分别为 `Stick together, team.` / `OK, let's go!` / `Fire in the hole!` / `Bombs on the ground here.` / `Keep going and stay strong, team.`）
2. **Given** 学生在今日测验 / 错题本专项 / 错题库专项页，**When** 点击"开始"按钮，**Then** 播放一次 `Come get some!`
3. **Given** 音效已开启，**When** 学生做清单外的任何操作（翻上一个 / 下一个单词、测验全部答完、完成一轮学习、切换导航、点击其他按钮、登录、保存设置等），**Then** 不发出任何声音
4. **Given** 学生短时间内在同一页面来回切换，**When** 同一页面的进入语音被重复触发，**Then** 不叠成串音（去重或直接覆盖），且回到该页面时仍能听到该页台词

---

### User Story 3 - 音效开关与音量控制（Priority: P3）

学生需要能自己决定要不要声音：设置页提供音效开关与音量调节，关掉后整个应用静音；选择在本台设备被记住。**首次进入默认关闭**，由学生自己打开。

**Why this priority**: 开关是前两条功能的"安全闸"，必须与音效同时提供，但本身不产生学习价值，故排 P3。

**Independent Test**: 进入设置页 → 关闭音效 → 全流程无声；重开浏览器 → 仍是关闭；再开启 → 声音恢复，音量调节生效。

**Acceptance Scenarios**:

1. **Given** 学生在设置页，**When** 将音效开关关闭并保存，**Then** 之后所有场景（连杀播报、答错、页面进入、开始）均无声，且设置页明确展示当前为关闭状态
2. **Given** 从未设置过音效的学生，**When** 首次进入应用，**Then** 默认为**关闭**状态，不发出任何声音
3. **Given** 学生已关闭或开启音效，**When** 关闭浏览器后重新打开并登录，**Then** 该设备保持上一次的选择
4. **Given** 学生开启音效后调节音量，**When** 后续语音播放，**Then** 按所选音量播放（最小档仍可听见，最大档不刺耳）
5. **Given** 学生在 A 设备开启、B 设备未设置，**When** 在 B 设备使用，**Then** B 设备按默认值（关闭）运行（音效偏好只属于设备，不随账号同步）

---

### Edge Cases

- **自动播放限制**：浏览器在未发生用户交互前不允许发声时，系统**静默跳过**语音，不报错、不弹提示；用户点击任意位置后语音自动恢复
- **连击快速推进**：连续快速答对时，新语音**覆盖**上一条（后播压先播），不排队、不叠加；连杀计数不受播放影响，始终准确
- **连击边界**：第 10 题播 `Deca kill`、第 11 题起播 `Good job`；答错随时清零，包括刚满 10 连对之后
- **新开一轮测验**：点击"开始"重新作答时，连对计数归零，答对第一题播 `First blood`
- **与单词发音冲突**：播放单词发音（朗读）时若同时触发语音，两者不互相打断、不重叠成噪声（单词发音优先或语音让位）
- **页面重复进入**：同一页面在极短时间内被重复进入时，不叠成串音（去重或覆盖）
- **资源不可用**：音源缺失、加载失败或设备无输出时，静默降级为无声，功能与界面不受影响
- **弱网 / 离线**：断网状态下语音仍可用（音源随站点提供，不依赖网络与外部服务）
- **后台标签页**：页面切到后台时不继续排队播放积压语音
- **无障碍**：连杀播报只是增强，对错的文字 / 颜色提示始终存在，语音不作为唯一信息渠道

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 在今日测验 / 错题本专项 / 错题库专项中，按**连续答对题数 N** 播放对应台词：1=`First blood`、2=`Double kill`、3=`Triple kill`、4=`Quadra kill`、5=`Penta kill`、6=`Hexa kill`、7=`Hepta kill`、8=`Octa kill`、9=`Nona kill`、10=`Deca kill`
- **FR-002**: System MUST 在连续答对超过 10 题后（第 11 题及以后），每题播放 `Good job`
- **FR-003**: System MUST 在答错一题时播放 `Storm the front.`，并将连对计数清零（下一次答对从 `First blood` 重新开始）
- **FR-004**: System MUST 让连对计数在一次测验流程内累计，并在**每次点击"开始"（今日测验 / 错题本专项 / 错题库专项）时归零**；不跨测验、不跨会话、不跨天保留
- **FR-005**: System MUST 在进入首页时播放 `Stick together, team.`
- **FR-006**: System MUST 在进入学习页时播放 `OK, let's go!`
- **FR-007**: System MUST 在进入测验页时播放 `Fire in the hole!`
- **FR-008**: System MUST 在进入错题页时播放 `Bombs on the ground here.`
- **FR-009**: System MUST 在进入总结页时播放 `Keep going and stay strong, team.`
- **FR-010**: System MUST 在点击"开始测验"或"开始专项练习"时播放 `Come get some!`（今日测验 / 错题本专项 / 错题库专项均适用）
- **FR-011**: System MUST NOT 为上述清单之外的任何交互发声 —— 包括但不限于：**进入专项练习页（错题专项 / 错题库专项不播进入音，仅在其页面点击"开始"时按 FR-010 播 `Come get some!`）**、翻上一个 / 下一个单词、测验全部答完、完成一轮学习（轮次达成）、导航切换、普通按钮点击、登录 / 注册、保存设置
- **FR-012**: System MUST 在设置页提供音效开关（开启 / 关闭）并明确展示当前状态，且**首次使用的默认状态为关闭**
- **FR-013**: System MUST 提供音量调节能力，最小档可听见、最大档不刺耳
- **FR-014**: System MUST 将音效开关与音量偏好保存在**本设备**，刷新页面与重开浏览器后保持
- **FR-015**: System MUST 在音效关闭时做到全场景静音，且不改变任何既有功能与界面反馈
- **FR-016**: System MUST 在未发生用户交互、浏览器不允许发声时静默跳过语音（不报错、不弹窗）
- **FR-017**: System MUST 保证语音播放不阻塞界面响应：答题反馈、页面渲染都不得等待声音结束
- **FR-018**: System MUST 在连续快速答题时以后播覆盖先播的方式播放（不排队堆积、不叠加成噪声），且不影响连对计数的准确性
- **FR-019**: System MUST 在每次进入页面时（含从其他页返回与刷新）播放该页台词一次，仅对同一页面**极短时间内**的重复进入做去重或覆盖，避免串音
- **FR-020**: System MUST 使用**自产英文短句语音**：由项目既有的朗读 / 合成能力预先生成并导出为音源文件，随站点一起打包发布；MUST NOT 使用任何商业游戏、影视作品或第三方素材站点的语音录音
- **FR-021**: System MUST 使所有语音呈现**高昂、激情**的语气（语速偏快、音高上扬），单条长度控制在 2 秒以内，清晰不刺耳
- **FR-022**: System MUST 使音源随站点一起提供、**离线可用**，且播放语音**不向任何第三方发起请求**
- **FR-023**: System MUST NOT 因音效采集、上传或统计任何用户行为数据（不新增埋点、不上报播放记录）
- **FR-024**: System MUST NOT 将音效偏好写入账号或服务端（不新增任何账号字段与个人信息）
- **FR-025**: System MUST 保证所有带语音的事件同时具备视觉反馈，语音仅为增强、不得作为唯一信息渠道（尤其对错提示必须始终可见）
- **FR-026**: System MUST 让**单词发音朗读优先于音效语音**：朗读进行中时跳过本次音效语音，既不打断朗读、也不排队补播
- **FR-027**: System MUST 在音源缺失 / 加载失败 / 无可用输出设备时静默降级为无声，不影响其他功能
- **FR-028**: System MUST 以**可配置映射**（事件 ↔ 台词 / 音源）定义上述台词，使单条台词的替换不影响触发逻辑、音量与开关

### Key Entities *(include if feature involves data)*

- **连对状态（Streak）**：一次测验流程内连续答对的题数；属性：当前计数、所属测验会话；答错归零、开始新测验归零；**仅存在于会话中，不写入服务端**
- **音效事件与台词映射（Sound Event Mapping）**：事件标识（页面进入 ×5、开始测验、连对 1–10、连对 >10、答错）↔ 英文台词 ↔ 音源；可单条替换
- **音效偏好（Sound Preference）**：仅存于本设备的用户设置；属性：开关状态（默认关闭）、音量档位；**不属于账号数据，不与服务端同步**

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 连答对 12 题时，台词顺序**100% 正确**：1–10 依次为 First blood → Deca kill，第 11、12 题为 `Good job`
- **SC-002**: 答错时播放 `Storm the front.` 且连对清零，再答对回到 `First blood`，**100% 复位准确**
- **SC-003**: 五个页面进入语音 + 开始语音共 6 类事件，**无串台、无遗漏**；清单外操作**0 次**发声
- **SC-004**: 学生点击答案后，对应语音在 **150 毫秒内**响起，主观上"点下去就有声"
- **SC-005**: 关闭音效后，全流程 **0 次**发声
- **SC-006**: 修改设置后刷新页面、重开浏览器，**偏好 100% 保持**
- **SC-007**: 首次进入页面到用户首次点击之间，**无声音且无控制台报错**
- **SC-008**: 断网状态下答题与进入页面，**语音正常播放**
- **SC-009**: 语音资源**不计入首屏**：站点首次可交互时间相对关闭时**增加不超过 1 秒**；音源在开启音效后才加载
- **SC-010**: 全程**不产生任何外部网络请求**（浏览器网络面板新增请求数为 0）
- **SC-011**: 快速连答 10 题时，语音**不叠加**，最后一次听到的内容与实际连对数一致

## Assumptions

- 台词文本由用户指定（2026-09-30），语音由项目既有的朗读 / 合成能力预先生成并导出为音源文件；**声音是自有合成音色，不复制任何商业游戏或第三方的原始录音**
- 语气基调为**高昂激情**（语速偏快、音高上扬），单条 ≤ 2 秒，适合初中学生的激励场景
- 连对计数仅在**单次测验流程内**累计，点击"开始"重新作答时归零；不跨测验、不跨会话、不入库
- 音效偏好只存在本设备，不进账号、不新增服务端字段，避免触发未成年人信息新增字段的合规审查
- 依赖既有能力：站点已有单词发音播放与"音频预热"机制（用于绕开浏览器自动播放限制），音效复用同一套播放时机约束
- 移动端与桌面端均需支持；iOS 等平台的自动播放限制按"用户手势后才发声"处理
- 本功能为纯前端体验增强，**不改动任何后端接口、不改动数据库结构**
