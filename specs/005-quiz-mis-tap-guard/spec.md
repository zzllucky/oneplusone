# Feature Specification: 测验防误触（Quiz Mis-Tap Guard）

**Feature Branch**: `005-quiz-mis-tap-guard`

**Created**: 2026-10-19

**Status**: Draft

**Input**: User description: "测验防误触：答题进行中离开需二次确认（含三个答题页），并加切题后选项防连点保护"

## Clarifications

### Session 2026-10-19

- Q: 在测验页点击底部这一排导航（首页 / 学习 / 测验 / 错题 / 总结 / 设置）时应如何防误触？ → A: 弹二次确认；在其他页面点击导航不弹确认
- Q: 二次确认应该在测验页的什么状态下触发？ → A: 仅测验进行中（已开始答题、尚未查看结果）；未开始与结果页不弹
- Q: 二次确认要覆盖哪些答题页？ → A: 三个答题页都覆盖：今日测验页、错题专项页、错题库专项页
- Q: 点了确认要离开之后，这一轮没答完的测验怎么处理？ → A: 离开即作废本轮，弹窗提示"未完成的测验不会保留"，返回后重新开始
- Q: 二次确认用哪种弹窗形式？ → A: 项目内自定义弹窗（与全站卡片风格一致），主按钮「继续答题」、次按钮「离开」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 答题进行中离开需二次确认（Priority: P1）

学生在任一答题页（今日测验 / 错题专项 / 错题库专项）答题过程中，误触底部导航（首页、学习、测验、错题、总结、设置）时，系统不立即跳走，而是弹出二次确认：提示"离开后本轮测验不会保留"，并提供「继续答题」与「离开」两个选择。选「继续答题」则留在原题、进度不变；选「离开」才真正跳转，本轮未答完的进度作废。

**Why this priority**: 这是最直接造成损失的一类误触（一整轮测验白做），也是用户明确提出的诉求；单独做完即可交付价值。

**Independent Test**: 在今日测验页答 2 题后点击底部"首页" → 出现确认弹窗且未跳走；点「继续答题」仍在原第 3 题；再点导航并选「离开」 → 跳到首页，回到测验页需重新开始。

**Acceptance Scenarios**:

1. **Given** 学生处于答题中（已开始、未查看结果），**When** 点击底部导航任一项（首页 / 学习 / 测验 / 错题 / 总结 / 设置），**Then** 弹出二次确认且不发生页面跳转
2. **Given** 确认弹窗已出现，**When** 学生点击「继续答题」，**Then** 弹窗关闭，仍停留在当前题目，题目与已答进度完全不变
3. **Given** 确认弹窗已出现，**When** 学生点击「离开」，**Then** 跳转到所点的目标页面，且本轮未完成的测验不再保留
4. **Given** 学生离开后再次进入该答题页，**When** 页面加载完成，**Then** 呈现未开始状态，需重新点击「开始」才开始新一轮
5. **Given** 学生在答题页但尚未开始（未点「开始」），**When** 点击底部导航，**Then** 直接跳转，不弹任何确认
6. **Given** 学生已答完全部题目并看到结果页，**When** 点击底部导航，**Then** 直接跳转，不弹任何确认
7. **Given** 学生在非答题页（首页 / 学习 / 错题 / 总结 / 设置），**When** 点击底部导航，**Then** 行为与现状一致，不弹任何确认
8. **Given** 学生处于答题中，**When** 通过浏览器的返回操作或手机返回手势离开，**Then** 与点击导航一致，同样弹出二次确认

---

### User Story 2 - 切题后短暂防连点，避免误选下一题选项（Priority: P2）

学生点「下一题」进入下一题的极短时间内，选项不可提交：此时手指的余下点击不会被判成选择了某个选项。短暂锁定结束后，选项恢复正常作答。

**Why this priority**: 这是用户最初抱怨的另一半（点"下一步"误触到下面的按钮），单独可测、可独立交付；但它不造成整轮丢失，故排在 US1 之后。

**Independent Test**: 答完一题后快速连点「下一题」位置两到三次 → 不会提交任何答案、不会听到答对 / 答错的音效；等待约 0.3 秒后点击选项 → 正常作答。

**Acceptance Scenarios**:

1. **Given** 学生刚点「下一题」切到新题，**When** 在锁定窗口内（约 0.3 秒）点击任意选项，**Then** 不提交答案、不播放答对 / 答错音效、不显示对错反馈
2. **Given** 锁定窗口已结束，**When** 学生点击选项，**Then** 正常提交并给出对错反馈与音效，与现状一致
3. **Given** 学生处于锁定窗口内，**When** 学生点击「下一题」或「查看结果」按钮，**Then** 该按钮不受锁定影响，行为与现状一致
4. **Given** 学生答题速度正常（每两题之间间隔大于锁定窗口），**When** 连续作答整轮，**Then** 无任何可感知的延迟或"点了没反应"

---

### Edge Cases

- 确认弹窗已出现时学生又点击了底部导航的其他项：不叠加第二个弹窗，仍以当前这一次确认为准
- 学生点「下一题」后请求较慢、下一题尚未渲染完成：锁定从新题可作答时开始计时，避免锁定窗口被加载耗时吃掉
- 学生在锁定窗口内点击选项，随后锁定结束：不发生"补提交"，该次点击作废，需重新点选
- 答题中刷新页面或直接关闭浏览器：属于浏览器行为，不做拦截
- 学生选择「离开」后：本轮未答完的进度作废，但此前已作答的记录仍保留在历史与错题本中，不受影响
- 弹窗按钮的可点区域与页面其他按钮一致，避免弹窗自身成为新的误触来源

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统在学生处于答题中（已开始答题、尚未查看结果）时，必须对离开答题页的操作（底部导航点击、浏览器返回、手机返回手势）进行二次确认
- **FR-002**: 确认弹窗必须说明"离开后本轮测验不会保留"，并提供「继续答题」与「离开」两个明确选项
- **FR-003**: 选择「继续答题」必须保持当前题目、当前进度与已提交答案完全不变
- **FR-004**: 选择「离开」必须跳转到目标页面，并作废本轮未完成的测验
- **FR-005**: 本轮作废后再次进入该答题页，必须呈现未开始状态，需重新开始
- **FR-006**: 作废仅影响未完成轮次的继续作答，已作答记录、错题本与历史数据必须保留
- **FR-007**: 学生在答题页但尚未开始，或已看到结果页时，离开不得弹出确认
- **FR-008**: 该确认机制必须在三个答题页（今日测验、错题专项、错题库专项）上表现一致
- **FR-009**: 非答题页的底部导航点击行为保持不变，不得弹确认
- **FR-010**: 切到下一题后，系统必须在极短时间内（约 0.3 秒）忽略选项点击，防止连点误选
- **FR-011**: 锁定窗口内的选项点击不得提交答案、不得播放音效、不得显示对错反馈
- **FR-012**: 锁定窗口不得影响「下一题」/「查看结果」按钮本身的响应
- **FR-013**: 锁定窗口结束后，作答交互必须立即恢复，且与现状行为完全一致

### Key Entities *(include if feature involves data)*

- **测验轮次（已有）**：一次"开始"到"查看结果"的答题过程，本次不新增字段，仅用于判定"是否处于答题中"
- **作答记录（已有）**：每题的作答结果，已逐条留存；本轮作废不删除已产生的记录

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 答题进行中点击底部导航，100% 弹出二次确认，不再出现直接跳走导致的整轮丢失
- **SC-002**: 未开始状态与结果页点击底部导航，弹窗出现次数为 0（不打扰既有流程）
- **SC-003**: 选择「继续答题」后，100% 停留在原题目，已答进度无任何变化
- **SC-004**: 选择「离开」后回到该答题页，100% 呈现未开始状态；历史与错题本数据无丢失
- **SC-005**: 切题后约 0.3 秒内点击选项，答案提交率为 0；锁定结束后作答成功率与现状一致
- **SC-006**: 人工完整走查一轮 20 题（手机与电脑各一次），因误触导致的非预期跳页或误选次数为 0

## Assumptions

- 主要使用场景为手机 / 平板触控，手指点击的目标区域普遍偏小，因此防误触优先于操作速度
- 确认弹窗文案面向初中学生，使用简短中文，不出现技术术语
- 浏览器返回与手机返回手势与点击导航同等处理，一并纳入二次确认
- 本轮作废沿用现有"未完成即不产生结果"的逻辑，不新增服务端接口与数据表
- 锁定窗口取约 0.3 秒：足以吸收一次连点的余下点击，又短到不影响正常答题节奏；实现阶段可在 0.2–0.5 秒范围内据实测微调
- 依赖既有功能：测验流程、底部导航、答对 / 答错音效（004 音效功能）均保持现状，本次只在其之上加保护
